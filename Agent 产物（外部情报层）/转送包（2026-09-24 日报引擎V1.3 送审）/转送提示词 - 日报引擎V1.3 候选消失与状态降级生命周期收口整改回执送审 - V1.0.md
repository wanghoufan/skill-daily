## 两个 Blocker 的修复

1. **候选消失静默（§一~§七）**：load_inputs 先做 old baseline vs current keys 的
   key 级 diff → `NO_LONGER_RELEVANT`；曾展示（或用户反馈过）的消失进入「暂不建议」桶，
   卡片带「之前的动作→现在→原因」可读信息（baseline/shown 已按 §十九/§二十 补存
   skill_name/source/source_url/last_display）；从未展示的 backlog 消失只记
   `suppressed.no_longer_relevant_unseen`（t64）。消失写 `candidate_tombstones`：
   notified 标记保证只通知一次（t65），`tombstone_retention_days=30` 可配置，
   未通知的重要项不提前清理（t74~t77），重新出现识别为 `RETURNED`（§八，只报一次，t66/t67）。
2. **install→reject 静默（§九~§十六）**：action/recommendation 迁移生成
   `STATUS_DOWNGRADED` / `STATUS_UPGRADED`（§二十一比较顺序第 3 步）；
   已展示过的降级必提醒（t68/t69），原因如实（产品范围/评分/需求变化 ≠ 安全风险，§十一），
   `risk_kind ∈ {security, source, no_longer_relevant, status_downgrade}` 机器层分清（§十四）；
   未展示降级只机器统计（§七十 → non_material_today + lifecycle.status_downgraded）。
